# CORE V9.6 — original authorized objectives and acceptance contract

Source: founder's V9.6 request in this session. Subsequent STOP instruction pauses all development; this document does not authorize automatic resumption. CORE HQ is frozen. Repository `~/core`; production https://creationofrebornearth.com; baseline V9.5 `0bc533ec312d882b40eccd252131dac509c7fd20`.

## Mission

Build actual autonomous multi-agent intelligence, rather than polish the demo: 500 specialized, intelligent, interconnected identities investigating real-world problems across the San Francisco Bay Area. Prioritize real model reasoning, authorized tool use, collaboration, persistent tasks and verified outputs. Preserve V9.5 design, commercial pages, manifesto and functioning features. No production promotion without approval.

## 1. Reuse open-source agent technology

Evaluate only relevant existing CORE infrastructure and these candidates:
- https://github.com/langchain-ai/langgraph
- https://github.com/crewAIInc/crewAI
- https://github.com/microsoft/agent-framework
- https://github.com/ollama/ollama
- https://github.com/gboeing/osmnx

Prefer LangGraph for durable stateful orchestration unless an existing solution is materially simpler. Choose ONE orchestration framework, not all three. Reuse infrastructure. Never imitate LLM reasoning with fixed trees, canned responses, keyword matching or prewritten agent conversations.

## 2. Real inference

An agent receives a goal, reasons about the next useful action using a real language model, selects authorized tools, executes them, inspects actual results, updates its plan, delegates when appropriate, produces structured evidence-linked output, persists and resumes.

Inspect and reuse authorized existing providers/models first. Implement provider abstraction and Ollama-compatible loopback support where feasible. Codex/Claude subscription credits are not application API inference. No silently paid model calls, auto-top-ups or hosting. If inference is unavailable, implement genuine integration and identify a local test provider explicitly; report exact missing configuration, never label mocks intelligent.

## 3. 500 functional identities

Each persistent record needs unique ID; specialized role; geographic responsibility; mission/goals; authorized tools; memory/history; team/supervisor; truthful task status; outputs and sources. Domains: mobility, housing, infrastructure, energy, water, climate, public safety, economic development, transit, planning, environment and cross-domain analysis. All 500 can receive genuine work through one shared bounded inference/worker pool, not 500 model instances. Idle never means thinking.

## 4. Hierarchy and collaboration

Central planner/coordinator, domain supervisors, specialist workers, evidence verification, simulation/quantitative tools, final reviewer and reporter. Agents create subtasks, delegate, share structured findings and collaborate on a common problem. Persist delegation, tool calls, model invocations and outputs. Bound iterations, budgets, concurrency and failures. No endless conversations.

## 5. Bay Area geography and movement

Cover San Francisco, Oakland, Berkeley, Richmond, Alameda, San Leandro, Hayward, Fremont, San Mateo, Redwood City, Palo Alto, Mountain View, Sunnyvale, Santa Clara, San Jose and surrounding communities. Use verified administrative boundaries and suitable OSM pedestrian geometry. No invented roads.

Weight assignments using real missions, population/infrastructure/available data rather than downtown clustering. Fix clustering. Preserve holographic humanoids, automatic appearance, visible valid street/path movement, selection exposing actual tasks and performance. Never fly over the Bay or cut buildings. Movement represents geographic missions, not active model computation.

## 6. Real problem discovery

Use permitted public agency/municipal/regional transport, planning/housing, environmental, infrastructure/resilience sources and relevant permitted news/announcements. Repeatable pipeline:

Source → candidate problem → geographic assignment → evidence check → explicit priority score → assigned team → analysis → stored report.

Rank using severity, affected population, recency, evidence quality and tractability with explicit assumptions; headlines alone cannot establish factual severity. Retain URLs, dates, units, coverage and licensing. Follow FD09 verified access/use rights; public availability alone is insufficient.

## 7. First complete autonomous investigation

ONE actual end-to-end investigation before breadth. At least planner, source discovery, evidence validation, geographic analysis, quantitative/simulation, reviewer and reporter. Planner chooses/delegates work. Workers invoke real tools and inspect outputs. Reviewer can reject weak evidence/request corrections. Final sourced, non-canned report names each contributor and actual accomplishments. Use an accessible, real Bay Area problem.

## 8. Scenario evaluation

Reuse/improve V9.5 computation. Connect actual measurements where available; missing calibration stays exploratory. Agents propose competing interventions, define assumptions, invoke the actual engine, inspect outcomes, compare trade-offs, reject unsupported claims and produce a decision report. Modeled success is not real-world success. No physical, municipal, financial or operational intervention without human authorization.

## 9. Persistent execution

Persistent task store and resumable lifecycle beyond browser demos. Reuse approved infrastructure. If hosting cannot run a persistent worker, provide a working local worker plus launch commands and explain requirements for continuous hosting. Do not claim continuous work without a running service or enable paid hosting. Public site shows authentic saved work, timestamps and honest worker availability.

## 10. Observability, without redesign

Per agent: latest/current real task; provider and execution state; tool invocations; sources; collaborators; outputs; failures/uncertainty.

Per problem: team; delegations; findings; calculations; scenarios; report; human-review status. No fabricated reasoning traces, tools or completion records.

## 11. Resource limits

No paid services without approval, surprise APIs, unlimited LLM loops, framework rewrites, full-repo audits, elaborate demo video, speculative 500-model deployment, CORE HQ changes or production promotion. Small actual worker pool. Measure returned token usage, latency, completion and failures; unknown usage must remain unknown.

## 12. Implementation order

A. Inspect why existing execution is not genuinely LLM-driven.
B. Connect working inference and demonstrate a real tool-using agent.
C. Persistent multi-agent delegation/collaboration.
D. Genuine verifiable autonomous investigation.
E. Bay Area assignments/visualization.
F. Existing-interface connection to real work.
G. Focused tests and protected Vercel Preview.

Do not substitute animation for intelligence. Identify inference dependencies immediately instead of pretending operation.

## 13. Acceptance test

Give a previously untested Bay Area question to the agent team. It must:
1. Plan the investigation.
2. Delegate to distinct specialized agents.
3. Retrieve and verify real external information.
4. Execute at least one appropriate analytical tool.
5. Share findings between agents.
6. Detect or explicitly report uncertainty.
7. Produce a sourced report.
8. Persist tasks and results.
9. Display actual work in CORE.

The outcome depends on retrieved data and real model/tool execution, not hardcoded responses. Separately verify Bay Area-wide placement and street-constrained movement.

## 14. Final reporting and honesty

Report only actual provider/model; persistent identities; concurrent real workers; evidence of tool use/delegation; one genuine completed investigation; geographic coverage; persistence and hosting status; costs/limits; blockers; commit and protected Preview URL. If genuine inference cannot run, mark intelligence milestone BLOCKED. Animation, deterministic scripts or browser smoke passes alone cannot establish success.
