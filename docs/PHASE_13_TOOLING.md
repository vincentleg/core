# Phase 13 — décisions d’outillage fondées sur essais

Inspection 2026-10-15 UTC, sans installation ni modification de compte. Runtime : Node v22.20.0 (`node:sqlite` disponible, expérimental), Python 3.9.6, SQLite CLI 3.54.0, Codex CLI 0.162.1. Chrome installé ; `playwright`/`playwright-core` non résolvables depuis CORE. Ollama répond sur loopback : qwen3:8b, Q4_K_M, fichier déclaré ≈5,23 Go. Présence d’un service ≠ adoption d’un nouvel outil. Outils MCP techniques de l’hôte disponibles ; aucun nouveau serveur produit ajouté, configurations privées non rescannées : inventaire personnel exhaustif **non vérifié**.

Cela montre de l’activité, **pas un audit de maintenance, sécurité ou licence de chaque composant**. Pas d’exécution de leur code pour départager des fonctionnalités sans besoin réel.

## Mesures bornées

`node scripts/research-experiment.mjs --record` produit `data/research/tooling-experiment.json`. Un échantillon : premier passage ≈8,1 ms, second ≈2,4 ms ; 7 événements puis toujours 7 ; 10 655 caractères de catalogue contre 543 caractères d’extraits pour 3 documents récupérés. Processus ≈53 MiB RSS, hors modèle. Le second passage **recalcule/vérifie encore**, mais évite les écritures dupliquées. Ces valeurs ne garantissent ni accélération générale, ni compression de contexte Codex, ni économie de tokens/coûts : **NOT_MEASURED**.

Essai Ollama : `node scripts/research.mjs --question examples/research/traffic-question.json --ollama`. Une première tentative avait échoué sur un chemin d’import avant tout appel ; corrigée, puis un seul appel effectif. Réponse non probante séparée du dossier déterministe, jamais publiée comme preuve. Pas de nouvelle dépense, API payante, compte, modèle téléchargé ou restriction contournée.
